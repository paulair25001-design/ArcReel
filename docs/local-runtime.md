# 本地 Hermes 与 L20 运行方式

本分支默认启用 `ARCREEL_LOCAL_ONLY=true`。项目、素材、分镜、任务队列、版本和剪辑导出全部由 ArcReel 管理；对话与后台文本任务调用本机 Hermes，图片和视频通过原生 ComfyUI API 调用自有 L20，旁白调用免费本地 Qwen3-TTS。任何本地失败都会保留错误，不转云端。L20 provider 的推理图、请求和资源会话代码都在本仓库内，不加载其他制作项目、factory、catalog 或技能工作流。

## 启动

在仓库根目录执行：

```bash
uv sync --locked
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
bash scripts/start_local.sh
```

打开 <http://127.0.0.1:1241>。默认保留登录认证，用户名为 `admin`；首次启动自动生成的密码保存在仓库 `.env` 的 `AUTH_PASSWORD` 中。启动脚本只监听本机回环地址。停止时在启动终端按 Ctrl+C，应用会先停止任务服务，再结束本应用拥有的 L20 会话。

没有已授权的自动目标时，启动工作台不会提交生成任务。已有活动自动目标会在启动后读取原生状态并继续，避免应用重启丢失制作责任。启动不会加载、重启 oMLX；Hermes 的模型必须已由本机 oMLX 提供。L20 在首次媒体任务进入本项目资源会话后才开始工作。

## Hermes 自动制作

本地模式的分集页提供「自动制作」入口。输入该集的最终目标并启动一次，Hermes 会沿 ArcReel 自己的源文、剧本、素材、分镜、视频、时间线与成片工具推进。授权包括该集制作中的内容确认和最小修复；无需每一步人工点击。没有这个明确目标时，普通聊天仍按原来的手动规则工作。生产运行不调用 Codex，也不调用其他项目的技能、工厂或编排脚本。

目标和同一 Hermes 会话的绑定保存在原生数据库。后台在队列落账后继续该会话，等待期间只检查数据库与任务状态，不反复调用模型。应用恢复时先对账，已有请求状态不明确时不重放上次生成命令。所有生产写入经过项目阶段屏障，配音、图片编辑或渲染未结束时不会进入下一阶段。连续三轮没有原生产物或准备状态推进会进入「需处理」，保留结果并安全归还资源，不假报成功或无限重试。

分集页可查看进度并打开自动会话；「停止自动制作」保存停止意图，等待已接受媒体任务结束后归还资源。停止或删除该自动会话也会停止目标，后台不会重新唤起它。自动目标的完成条件是该集指定的 `current` 原生成片，旁白项目必须带完整旁白和烧录字幕，且本目标的 L20 会话已按模型恢复设置完成收尾。后台还核对本目标创建后实际成功的 `finish_local_session` 收尾，收尾须晚于最后一次原生审片与生产写入；旧成片或模型自述的批次不代表本目标完成。完成状态是技术完成，不代表真实听审、连续播放或口型验收。此入口不授权发布或向外发送。

对应原生接口为 `POST /api/v1/projects/{project}/autonomous-production`，请求包含 `episode_id`、`objective`、`client_key`；可选 `resume_session_id` 续接同用户、同项目拥有的 Hermes 会话，复用有效报告与未变化的媒体，原目标历史保持原样；相同用户、项目和 `client_key` 幂等，不能同时建立两个活动目标。`GET .../latest` 与 `GET .../{run_id}` 查询状态，`POST .../{run_id}/stop` 停止。接口继续使用工作台登录认证，项目与用户身份按原生范围校验。

声音交付按原生 `SpeechAdmission` 区分：角色对白不要求旁白 WAV，所用视频必须有实际音轨、版本记录允许原声且时间线未静音；画外旁白仍要求完整、有效的本地配音及唯一承载片段，并静音该镜头的视频原声；静默镜头可以保留环境声。混合或无效发声归属不能完成目标。成片变体沿用项目原生默认，含画外旁白时必须带旁白，字幕继续烧录。这些机械检查不证明角色对白逐字准确、声线一致或口型已通过听审。

目标进入「需处理」后，修复具体原因可选择「重试同一目标」：`POST .../{run_id}/retry` 携带当前 `expected_revision`。该恢复保留目标、SDK 会话和已有媒体，只发新的状态对账轮，不重放旧工具命令；相同修订的重复请求幂等。已停止或已完成的目标不会被复活，也不能覆盖另一个活动目标。

## 原生技能与审核子智能体

Hermes 使用 `agent_runtime_profile/` 按项目创作类型投影的同一套原生配置。主会话加载当前模式规范和文档目录，通过宿主 `read_agent_profile` 按需取得原文；`dispatch_agent` 对应原生子智能体派发，使用隔离的本地 Hermes 子会话执行原有 agent 定义及预载技能。工具结果超过原生显示上限时，`read_file` 只能分页读取当前会话的工具缓存，不能读取配置、其他会话或普通项目文件。这些工具仅适配宿主能力，业务操作仍经原有 MCP 工具。

资产图与分镜图沿原生 `review-images` 审查，剪辑沿 `edit-video` 的首轮全量 `review-footage` 审查和重生成后比较规则。审核子会话实际接收图片或视频联系表，主会话接收文字报告；只读角色的工具权限在运行时裁剪，不具备生成、修改或再次派发权限。模型、采样、思考和压缩参数继续沿用公共 Hermes 配置，所有子会话固定本地路由，不启用云端回退。MCP 已返回的结构化业务拒绝保留原错误，不计为连接故障；真实超时与断连仍使用 Hermes 原生断路器。

自动目标的渲染与完成会核对所用原生视频版本是否已有实际审片报告；新版本需要对应报告。恢复会话会重新取得匹配当前视频版本的原生报告全文，按子会话与报告 SHA 去重，保留“存疑、建议修复”等原始意见。报告仍由原生审片规则解释，完成覆盖不代表质量评分通过。抽帧检查不证明实际听审或连续播放；原生规则要求报告的遗留问题会随结果交付，不自动无限重新生成。

## 实际模型与输入约束

| 用途 | 路线 | 当前约束 |
| --- | --- | --- |
| 对话、规划、结构化文本及图片理解 | 本机 Hermes → oMLX | 固定配置的本地模型；Hermes 使用当前项目的 ArcReel MCP 工具及原生技能读取、子智能体派发适配 |
| 文生图、图片编辑 | L20 Qwen-Image 2.1 INT8 | `1K` 画布预设；16:9 为 1024×576，9:16 为 576×1024；图片编辑最多四张参考图 |
| 图生视频 | L20 FastH3 V2 | 默认原生对齐画布 `736p`（横屏 1280×736）、24 fps、1～10 秒；兼容已指定的 720p、576p；必须有首帧和明确的目标尾帧；不支持参考生视频或参考音频 |
| 旁白 | 本机 Qwen3-TTS VoiceDesign | 免费、离线；用声音描述和逐段演法控制配音，不支持数值语速或自动付费回退 |

默认 `736p` 预设把接近 720p 规模的画布向上对齐到 32 像素：16:9 项目生成和输出均为 1280×736，9:16 项目均为 736×1280，实际视频宽高比以对齐后的尺寸为准。此预设不补边、不裁成 720p，也不把低分辨率成片放大。首尾帧保留原始 PNG 字节和观察证据，由 H3 原生节点映射到生成画布，可复用已有完整分镜图。已有任务按冻结的分辨率继续；显式 720p 任务仍以补边生成、裁边输出准确 720p 的方式执行。

原生视频审片每段默认抽取 24 帧，每张联系表最多 12 帧。每次审片至多四段，避免 96 帧的调用预算摊薄密度；疑似短暂光影或变形以每段 48 帧复查，每次至多两段。审片子智能体须把明确缺陷标为排除区间，无法完成脚本动作的版本标为不可用。在自动制作修复授权内，主 Agent 经原生工具重做并比较、复审新旧版本；重做仍不可用时按原有停止规则报告，不以报告齐全代替质量通过。抽帧审片覆盖所有选用视频版本，仍不等于逐帧审核、真实听审或成片连续播放验收。

图片编辑会保留原图，把发送的参考图按画布等比缩放并补边，记录转换和两份 SHA-256。最多发送四张参考图，超过四张会拒绝，不静默丢弃。此限制由本项目调用通道统一声明；已安装原生节点提供更多槽位，不代表本接入已经验证更多参考图的实际资源占用。

本地流程使用逐镜生成的完整画布分镜。上游宫格功能切出的单格尺寸较小，为保留人物和场景细节，应先为每镜生成完整画布图片，再设置相应的目标尾帧。

在分镜界面选择或上传目标尾帧；Hermes 也可用 `set_storyboard_end_frame` 从项目内已有图片建立尾帧快照。尾帧表达镜头结束时的实际画面，不自动复制首帧。缺少尾帧时，视频任务在入队前被拒绝。

FastH3 原生生成音轨，不接受参考音频，也不支持关闭原生音轨；关闭音频的项目设置会在生成前被拒绝。旁白可在后期按时间线混音。

FastH3 的原生对齐帧数可能超过声明时长，适配器保留原片，并截取请求时长所需的前段帧，不改变播放速度。文件可解码、帧数和哈希通过，只代表技术检查，不代表画质、表演、听感或口型已经通过审核。

## 资源与会话

图像和视频共享本项目的 L20 GPU 锁。每个未提交的生成任务按当时的 router 和模型状态开工：先停止本项目遗留且已空闲的媒体服务，读取当前模型集合，卸载 llama 模型，再启动图片或视频推理服务。任务结束并取得产物后，执行器释放媒体模型、关闭本项目拥有的服务并恢复原模型。新任务不拿上一轮保存的 router PID 或启动时间作准入条件；恢复也通过当前 router 执行。模型权重、已安装 ComfyUI 和纯推理节点属于运行依赖，项目队列、审核与剪辑仍由 ArcReel 管理。

本机设置 `ARCREEL_L20_RESTORE_ORIGINAL_MODELS=true`、`ARCREEL_L20_STANDBY_MODEL=qwen3.6-27b-mtp`。即使 27B 在本轮开工前已被卸载，收尾仍恢复这个明确配置的待机模型；仅恢复当前模型目录仍提供的原模型，不把已移除或改名的旧模型别名带入新 router。每个模型的加载请求须等到实际 loaded，再加载下一个，27B 待机模型最后加载，避免异步启动同时分配显存。恢复核验模型已加载、router 健康及 GPU 驻留，不要求刚恢复的服务停止响应其他用户。该设置不拦截其他用户请求，也不增加占用检测、自动暂停或空闲等待。

已提交而结果未明的任务保留原 handle、请求图和服务，按原生队列与历史对账，不能重新发送。确定的生成失败也收尾恢复；产物已成功下载后，单独的模型恢复失败不会把有效图片或视频改成生成失败，恢复责任和错误保留在资源记录中。未提交的失败任务可重新准入，不沿用失效的上一轮进程身份。

整集交付或用户停止制作时，Hermes 调用 `finish_local_session` 核对最终收尾；它仍须晚于原生审片与生产写入。停止、删除会话或应用退出时先等待已接受的媒体作业落账，再清理本项目资源并按当前设置恢复待机模型。若显式改成 `ARCREEL_L20_RESTORE_ORIGINAL_MODELS=false`，则关闭媒体服务后保持原模型卸载，记录 `state=closed`、`resource_released=true`、`original_service_restored=false`；未完成的恢复不假报成功。

每个媒体任务在提交前冻结实际推理图、输入 SHA-256 和 provider handle，然后只提交一次 `/prompt`。已取得 `prompt_id` 的任务直接查询 `/history` 并通过 `/view` 下载。提交响应丢失时，只从队列和历史记录中按同一 handle、图内容与图哈希精确定位；无匹配或有多笔匹配均保留故障，不盲目重投。完成历史中的 graph 必须与冻结请求完全一致。

Hermes 配置、会话绑定和项目专用 MCP 密钥保存在本应用数据根的 `runtime/hermes/`；独立 L20 provider 的状态和恢复记录在 `runtime/l20-direct/`。不会修改全局 Hermes 配置或其他制作项目的授权。后台文本调用每次使用独立、无工具上下文；交互会话可以恢复，但当前不支持改写历史消息。

`inspect_images` 与 `inspect_video_units` 的原生 MCP 图片经本项目的 Hermes 子进程桥接，以 `arcreel-mcp-vision/v3` 传输。同一个本地视觉模型接收真实 `image_url` 内容；为兼容 oMLX 会把工具消息压成文字的处理，图片作为标明工具来源的 user-role 数据附在完整工具返回批次之后，工具文字及调用 ID 保持原身份。图片数据不构成新用户指令或授权，思考、采样与其他生成设置保持原值。旧 `MEDIA:path` 文本与 v2 工具消息带图记录不证明有效观察，须重新观察现有图片；旧审片报告按当前原生配置指纹重新判定，不删除历史。子进程私有目录的 `vision-wire-audit.jsonl` 记录实际 HTTP 请求的图片计数、角色、字节哈希、请求体哈希、固定本地端点与模型匹配结果，以及响应状态，不记录图片编码、提示词或认证头。图片缺失、被客户端降为文字、模型或端点不符时，在发送前拒绝；浏览器和普通日志只接收文字摘要。

自动目标的生成视频和成片渲染准入还会核验真实观察回执，不能凭模型自述绕过。原生看图工具从同一次源文件快照计算原文件、RGB 像素及实际 JPEG 三个 SHA；消费者关联同一 SID 和 transport 的实际主请求、2xx 响应及观察事件，再核对当前首帧和绑定尾帧的具体版本。辅助摘要不会产生观察事实，也不会先删除尚未送达的图片。生成视频首次提交前，还会检查任务私有目录内实际冻结的首尾图并再次复核正式输入，防止用已看过的新图替未看过的旧输入背书。手动模式无自动目标时不增加该门槛。回执证明实际图片送达，不代表模型判断正确或画面质量验收通过。

Hermes 的 HTTP 资源屏障由本仓库的 `lib/local_runtime/resource_queue.py` 提供，锁文件保存在本应用数据根的 `runtime/resources/`。每个本地文本 HTTP 请求只在实际请求和响应消费期间持有共享锁，工具执行不占锁；配音持有独占锁，等待中的配音优先于后来的文本请求。锁等待可取消或超时，不停止其他服务。

本地配音使用项目中的 `narration_voice_description`（声线描述）和 `narration_instructions`（项目默认演法），未设置时使用本地默认值。创建或修改项目的 HTTP 接口接受这两个字段；Hermes 可通过 `create_project` 设置，或通过 `patch_project` 的 `settings` 修改。传入空字符串或 `null` 可清除已存值，恢复本地默认值。任务会冻结实际使用的描述与演法，并记入版本依据；修改后，旧配音会按依据变化重新判定时效。界面目前没有编辑这两个自然语言参数的输入框。

后台结构化文本任务向 oMLX 提交原始 JSON schema，并同时请求 `response_format` 与显式 `structured_outputs`。每个新 worker 的 `wire-audit.json` 只保存实际 HTTP 出站的端点、模型匹配标记及两处 schema 的哈希，不保存提示词、密钥、HTTP 头或响应正文。约束在传输过程中缺失或改变时，worker 在发送前拒绝请求。该回执证明实际提交的约束，不证明服务端 logits processor 已执行；后者仍需服务端运行证据。历史任务不会补写回执。

主推理和原生压缩的参数只读继承 `~/.hermes/config.yaml`：包括思考等级、采样、上下文与输出预算、压缩策略及总时限。本项目不再另设摘要预算、关闭主思考或猜测新的超时值，也不选择未指定的具名 profile。项目仍单独限制本地模型路由、ArcReel MCP 工具权限、免费本地语音与资源屏障，不把全局工具、旧制作技能或云端回退带进来；公共文件与全局 oMLX 设置不会被修改。达到长度上限、超时或未完整提交的摘要仍不当作成功，原始会话保留供原目标继续对账。

Hermes ACP 的原生 Agent 工厂未传入 CLI 的思考与迭代参数，因此本项目在每次新建或恢复 Agent、首次请求前，用 Hermes 自身的配置解析器补齐 `reasoning_config` 和 `max_iterations`；子智能体沿原生构造继承主会话参数。不会为正在使用的 Agent 重置预算，也不覆盖采样、输出预算或压缩设置。

公共配置要求压缩前 checkpoint 时，本项目为该隔离 Agent 安装 Hermes 原生 manager-level API v2。完整原始会话与 normalized evidence 保存在当前私有 home 的 `checkpoints/pre-compress/{SID}/{SHA}.json`；文件 `0600`、目录 `0700`，经原子发布、文件及目录 fsync、SHA 回读验证后才返回引用。摘要失败不删除原始会话或已有 checkpoint。这里只提供项目内的上下文检查点，不加载全局外部记忆插件、其状态工具或旧制作流程。

本地配音原始执行回执保存在 `runtime/tts/receipts/`，版本记录绑定原始回执哈希及实际提交的 WAV。回执中的「未听审」状态保持原样。

原生制作状态的 `units[].speech_timing` 分开报告按项目语速估算的发声时长、实际旁白 WAV 时长、超出编排的秒数与音频时效。全自主 storyboard + TTS 制作可先经原生配音工具补缺，再用实测时长复核视频预算；视频准入仍只消费正式脚本与模型能力，不增加配音依赖。已有素材与旧配音不会因此自动重生。

每条原生时间线的 `editing_facts` 汇总定格秒数及占比、同版本源片重复使用的区间、同镜与异镜转场数量和旁白文件间隔。间隔可能包含角色对白或其他画面，并不等于静音；这些字段是剪辑事实，不是质量评分或新的阻断闸门。主 Agent 按原生审片报告处理每次复用的可用区间，交付时区分源片抽帧、成片检查与实际听审，未提供声音感知证据时保留未验证。

配音由本仓库的 `lib/local_runtime/qwen_tts_worker.py` 直接调用已安装的独立 MLX Audio 引擎库。模型必须是已存在的本地 Qwen3-TTS VoiceDesign；引擎运行在禁止网络的 macOS 沙箱中，并关闭模型下载、参考音频转录、自动播放与云端回退。声音输入经权限为 `0600` 的项目私有请求文件传入，不出现在命令行或正常标准输出中；完整 PCM 验证后才登记版本。项目代码不调用外部 skill wrapper、旧制作流程或它们的锁文件。

本地配音进程非零退出时，`runtime/tts/receipts/failures/` 保存私有失败回执、脱敏 stdout／stderr 和命令摘要，权限为 `0600`。失败提示仅显示识别出的保护原因和回执路径，不显示旁白原词、声线描述、演法或密钥。保护锁忙时保留当前任务，等待资源释放；不停止其他服务，不自动重试或转付费。未保存诊断的历史失败无法事后确定具体原因。

## 可选环境配置

配置写入仓库 `.env`，重启本应用后生效；不要把本机绝对路径写进共享工作流。

```dotenv
ARCREEL_LOCAL_ONLY=true
# 本机 oMLX 的回环地址，禁止配置公网地址
ARCREEL_HERMES_BASE_URL=http://127.0.0.1:8000/v1
# 若本机服务启用认证，填写它已有的本地 API 密钥
# ARCREEL_HERMES_API_KEY=
ARCREEL_HERMES_MODEL=Qwen3.8-Flash-Next-Uncensored-oQ5e-mtp
# 以下默认使用当前机器已有安装，可覆盖安装路径
# ARCREEL_HERMES_SOURCE=/path/to/hermes-agent
# ARCREEL_HERMES_PYTHON=/path/to/hermes-agent/venv/bin/python
# ARCREEL_TTS_PYTHON=/path/to/offline/python3.11
# ARCREEL_TTS_SITE_PACKAGES=/path/to/installed/mlx-audio/site-packages
# ARCREEL_TTS_MODEL=/path/to/qwen3-tts-voice-design
# 本项目管理的 SSH 回环转发；不接受云端 ComfyUI URL
ARCREEL_L20_SSH_TARGET=my-l20
ARCREEL_L20_SSH_OPTIONS_JSON='["-o","BatchMode=yes","-o","StrictHostKeyChecking=yes"]'
ARCREEL_L20_COMFY_URL=http://127.0.0.1:18191
ARCREEL_L20_ROUTER_URL=http://127.0.0.1:18080
ARCREEL_L20_RESTORE_ORIGINAL_MODELS=true
ARCREEL_L20_STANDBY_MODEL=qwen3.6-27b-mtp
# ARCREEL_L20_DIRECT_STATE_DIR=/path/to/arcreel-data/runtime/l20-direct
# ARCREEL_L20_COMFY_PYTHON=/path/to/installed/comfyui/python
# ARCREEL_L20_COMFY_ENGINE=/path/to/installed/ComfyUI
```

`my-l20` 应替换为已配置并验证主机密钥的 SSH 目标；需要跳板时，在 JSON 参数中显式加入 `-J` 和跳板名。SSH 连接与回环转发由本项目代码创建，远端使用独立的 ArcReel 输入、输出与服务目录。当前接入绑定已验证的 L20 主机 UID、`/nvme1` 挂载、模型目录与 router 端口；迁往其他服务器前应先调整并验证 `l20_remote_resources.py` 的主机配置。

本模式禁用其他供应商的连接测试、模型发现和端点试运行，关闭官方目录同步及官方服务。无需填写云端密钥。显式设置 `ARCREEL_LOCAL_ONLY=false` 仅用于上游兼容性开发与测试；本地启动脚本始终强制开启本地模式。
